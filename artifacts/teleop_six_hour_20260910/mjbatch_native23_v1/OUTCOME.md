# Native23 mjbatch offline MPC probe

The native23 adapter passes physical-model, PD-servo, reference-geometry and cost-gradient checks. Native MuJoCo3.2.3 H30 planning completes the original walk002 lifecycle, but crosses an ankle limit. An ankle-only cost ablation instead crosses a knee limit. Explicit floor-compatible v4 retarget runs also fail physical limits; walk003 tracks its source well until the crossings, while walk002 loses balance early. Fixed-plan feedback is fragile. No full-motion teacher or teleoperation qualification is established.

## Contract

- Original native23 model: nq30, nv29, nu23, nbody25 including world. Portable bundle restores unrounded model arrays after XML loading. Native masses, geometry, contacts, armature, damping, friction, limits and 2ms Euler integration remain unchanged.
- Every committed control is executed on the original torque-actuator model: BFM kp/kd, measured joints each 2ms, native effort caps. Planning uses algebraically equivalent affine PD actuators, with native target and force bounds.
- Physical state is initialized once at selected optimization reference frame10. Original goals use the original pose; the explicit validated retarget override uses its own frame10 and binds that distinction in the request. No later planned-state assignment, root force, hidden reference height lift, removed source frames or time scaling.
- Original 50Hz reference is preserved. H15 previews300ms; five controls are committed per plan. Each plant control contains ten2ms physics steps. A fault can stop the last control early; `physics_substeps` records that exact count.
- Body pose, joint pose and velocity costs use native references. Measured near-limit joints and excessive joint speeds receive explicit costs; raw2ms limits are reported independently. Crossing.01rad aborts the diagnostic, while any positive range excess remains unqualified.
- `feedback_gain` is the upstream solver's last backward sweep reused about its accepted trajectory. It is saved as controller provenance, not claimed to be a Jacobian of an exact optimized teacher.
- Optional BFM seed uses recorded executed targets only. Each window compares their physical rollout cost against the shifted previous plan, then optimizes the cheaper candidate from measured state. Saved BFM states never initialize the plant or candidate trajectory. The seed is checked against every original joint/root error and initial state, and both seed trace/report hashes are bound.
- Seeded preview includes the source generator's140ms goal window: H15 has300ms cost preview and conservative440ms effective source preview. This cannot be presented as the received-only140ms stream controller.
