# Independent plant clock foundation v3 — source preparation only

V3 fixes the three fake-only root review findings: a verifier could return a mutable issue dictionary, warnings could contain a mutable dictionary inside a tuple, and a backward finish timestamp could pass timing. The complete v2 sources, tests, examples and report remain unchanged as historical evidence; its earlier shallow-immutability claim was incomplete.

The verifier now returns only `None` or an exact nonempty string of at most 1,024 characters. Its returned value is copied into typed diagnostic bytes before validation. An invalid return retains the valid captured state and gets no verified or committed credit. A caller cannot mutate the saved issue through either the original returned object or a summary.

A capture is credited only after the complete structural adapter contract validates: exact `CapturedStep`, finite nonnegative Python float simulation time, nonempty immutable state bytes of at most 16,384 bytes, finite native23 float64 torque bytes, and an exact `WarningLedger`. The ledger has eight-int32 count and lastinfo tuples; counts are nonnegative and all elements are exact Python integers. Tuple subclasses, nested objects, lists, booleans and out-of-range integers are rejected. The accepted record consists only of immutable typed values.

Invalid capture returns are copied into stable typed diagnostic bytes before validation. `last_capture` remains empty and captured/verified/committed counters stay unchanged for that returned step. The actual step still receives attempted/returned credit. Diagnostic copying has explicit depth, element and byte-prefix limits; truncation and unsupported types are labeled. Large byte payloads retain size and full SHA256. Unknown objects are described by type without calling custom repr. This diagnostic is distinct from a valid capture and never substitutes for native state proof.

Every plant clock read now requires nonnegative, monotonic integer nanoseconds, including initial admission, copied-result validation, boundary/job creation, wake, finish and summary. A backward or malformed reading latches the first clock fault. A backward finish preserves the known returned/captured state without manufacturing a committed step with impossible timestamps. An invalid current clock has no honest current-debt value, so the summary reports null and retains the last valid reading. Later valid readings do not erase the failure.

Scheduling remains fixed at `epoch + index * 2,000,000 ns`, with ten-step control boundaries, no skipped indices or deadline rebasing. Attempted, returned, captured, verified and committed counts remain separate. Expected simulation time still uses repeated addition of 0.002. Existing activated raw-action provenance, held-command intervals, source-index gaps, four-lag history ownership, copied result identity and nonblocking try-lock rules are unchanged. History and mailbox source files are byte-identical to v2.

Seventy deterministic tests pass, including the original 41 cases and the three root probes. The first v3 test run had one test assertion error because it searched for the decimal string `99` anywhere in hashed diagnostic bytes. The assertion was corrected to inspect the typed warning value; the failed test report remains preserved. Two 50-step examples and three one-step root regressions are retained as fake-only ledgers.

This is **source preparation**, with zero MuJoCo/native, controller, ORT or optimizer calls, and no installed runtime. State bytes are an opaque structural payload here; full291 layout, native forces/quaternion/range oracle and actual simulation clocks still require a native adapter. Python containers, allocation, in-process mailbox storage and lock stubs do not prove actual shared-memory/process nonblocking behavior or wall-clock performance. Goal packet admission, preceding task sample, 38-sample completeness, delay-aware controller forecasting, quiet standing, recovery and hardware remain unimplemented or unqualified. Mechanical target holding is not balance qualification.

The final `preparation_report_v3.json` pins the source, all tests and examples, root findings, preserved v2 evidence and unchanged original runtime files. Root owns review; no second reviewer execution was requested.
