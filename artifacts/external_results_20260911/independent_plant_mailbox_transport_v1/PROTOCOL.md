# Fixed shared-memory mailbox, protocol 1

This is source preparation and synthetic spawned-process evidence. It does not connect a real plant, worker policy or clock run, and it does not qualify a 2 ms or 20 ms deadline.

The original clock/history/mailbox sources are copied unchanged for contract tests. NativeStepper v3 remains unchanged and is not imported or executed. Only immutable Job/Result bytes cross the transport; native model/data objects and mutable measured-history arrays remain plant-owned.

Create one mailbox per direction before admitting the epoch with an explicit `multiprocessing.get_context('spawn')`, a fixed slot count and payload capacity, and a 32-byte token derived from the canonical full Binding bytes. Pass the endpoint through `Process` arguments. Shared `RawArray` storage and one shared multiprocessing Lock per slot replace the original bytearray and process-local fields. Each operation tries each required lock exactly once using `acquire(False)`. There is no mailbox retry, timeout wait, queue, manager RPC, disk I/O or wake/sleep path.

Each slot contains a 100-byte little-endian header and its fixed payload region. The header contains magic, schema, state, uint64 key, uint64 publication version, uint32 length, 32-byte epoch token, and 32-byte payload SHA256. An empty slot transitions to WRITING under its lock, receives the payload, and transitions to FULL only after the complete bytes and digest are ready. Consumers copy and validate the full payload while holding the same lock, return an immutable Publication, and then clear only the header. Occupied slots never overwrite older or newer records. Versions increase on successful publication and remain stored after consumption. No assumption of atomic struct writes, atomic Python assignments, or a lock-free memory ordering protocol is made.

The ring index is key modulo slot count. A producer cannot publish into an occupied slot: it gets FULL. BUSY means the single nonblocking lock attempt failed. A wrong endpoint token returns WRONG_EPOCH without acquiring locks or consuming any record. Malformed headers or payload digest mismatches return CORRUPT without exposing or reclaiming bytes. A Python exception before final commit leaves UNCOMMITTED. A writer that dies while holding a multiprocessing semaphore may leave its slot permanently BUSY. The plant-side operation still returns; there is deliberately no forced unlock, owner-death repair, abandoned-record takeover, or shared reset in an active epoch. Replace the mailbox only after stopping and joining all peers and admitting a fresh epoch.

The transport envelope does not replace the existing clock's binding, sequence, snapshot/input digest, activation, duplicate and deadline checks. Generic transport keys can be reused after consumption; an old application packet must still be rejected by `PlantFoundation._admit`. Tests send wrong epoch, wrong sequence, late and duplicate packets through a spawned publisher into that unchanged pure admission logic, without a plant tick or native call.

Bounds are explicit: 1–1024 slots, 1 byte–1 MiB payload capacity, at most 64 MiB total shared allocation, uint64 keys/versions, and at most 4096 canonical binding bytes. Version exhaustion fails closed. These bounds narrow the prototype's formerly unbounded Python integer/configuration surface; admitted real-run sizes and packet lengths must be checked before any future integration. Storage does not grow, wait for room, overwrite or evict. Empty payload bytes are allowed by transport, while the application decoder remains authoritative.

Minimal future integration changes are replacing the jobs/results mailbox constructors and passing those shared endpoints into spawned workers; `try_publish(key, bytes)` and `poll_once()`/Publication remain compatible. Add fixed-capacity event handling for transport-specific UNCOMMITTED/CORRUPT/WRONG_EPOCH/CLOSED/VERSION_EXHAUSTED statuses. The current unchanged foundation safely admits only TAKEN records but does not yet log those additional status names. Keep its authoritative receive timestamp after decoding/copying, sealed activation, previous-command/history update, native step count and clock deadlines unchanged. No integration change is made here.

Limitations: synchronization is nonblocking, but copying, hashing, Python allocation, the scheduler, page faults and the GIL still take time. The synthetic watchdog is not a real-time guarantee. The protocol assumes trusted same-host peers; shared-memory access is not an authorization boundary and SHA256 is a corruption check, not authentication. Endpoint close is process-local; shared allocation lifetime follows references and joined process handles. Old unused bytes are not zeroized. The implementation is exercised on this Windows spawn runtime; another OS/runtime needs its own validation. Test-only events, pipes, waits, retries and intentional process death coordinate fault injection; none is present in a mailbox operation.
