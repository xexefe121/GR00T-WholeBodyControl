# Pending-result saved audit preparation

This is a source-only independent adaptation of the reviewed pending-job saved auditor. No actual clock request, audit request, launcher, worker, native step, model call, or optimizer execution is selected by this package.

The original native packed373/full291 reconstruction, manual PD and strict limits, repeated simulated time, fixed epoch and outer deadlines, history ownership, recorded source windows, held-command intervals, process/owner/input/output accounting, four MJB comparisons, stage watchdog checks, and pending-job BUSY audit remain unchanged. Job reconstruction now independently includes `deadline_ns = epoch_ns + activation * 20_000_000`. Admission preserves the original order while checking that literal deadline before full issued identity. It additionally rejects boolean activations as non-integer schema data.

`worker_result_math.py` imports no producer implementation. It reconstructs exact ready/result bytes from issued job identity, recorded target/action, and original completion stamp; correlates transport and worker attempts; enforces one attempt per worker iteration, consecutive BUSY retry iterations, the 20-attempt cap, original deadline, no recomputation, no new-job polling while pending, exact terminal reasons, and retained buffered work. It independently rebuilds all counters from events and final owned descriptors. Unknown returns, reserved logger records, uncomputed failed inputs, and possible plant receipts after an ambiguous write retain separate accounting. A bad recorded command can remain evidence-consistent while failing command qualification.

The worker does not log EMPTY poll spans. Empty poll counts are therefore cross-checked against the reviewed source loop and recorded iteration/retry/buffer counters; exact timing of those omitted polls cannot be independently reconstructed. The report states this limit. A missing final worker report cannot substantiate received results, and incomplete/hard-timeout output never receives component qualification.

The dormant request gate requires explicit `worker_result_retry_contract = immutable_result_BUSY_max20_original_deadline` and `job_deadline_contract = plant_epoch_plus_activation_20ms`, plus the unchanged pending-job contract. It pins the actual worker, protocol, pending-result module, core, runner, watchdog, and original comparison sources. Existing owner, concrete review, final output, PID absence, and pre/post input hashes remain required. All physical, command, timing, worker, and evidence-integrity verdicts stay separate.

Synthetic validation so far: an initial full suite passed 126 tests plus 26 subtests; the final worker helper passed 26 focused tests after six added failure/buffer/schema tests and narrow corresponding checks. A final combined suite is deferred while the separately selected canonical controller collects timings. Source is frozen for independent review; the reviewer can bind its own final combined result once compute is idle.
