# Native adapter v2 preparation

V1 and its review remain unchanged. V2 fixes the incomplete model fingerprint and failure-state preservation. All 23 injected tests passed; no real MuJoCo model, serializer, forward call or native step was executed.

The pinned 3.2.3 C headers expose `mj_sizeModel` and `mj_saveModel`. That version's serializer writes the complete model integer/pointer-array schemas and the full options, visual and statistics structures while omitting process pointer addresses. Its Python binding accepts a writable uint8 buffer. [Engine source](https://github.com/google-deepmind/mujoco/blob/3.2.3/src/engine/engine_io.c#L626), [Python binding](https://github.com/google-deepmind/mujoco/blob/3.2.3/python/mujoco/functions.cc#L102).

`FullModelIdentity` therefore compares the entire immutable expected MJB byte payload and SHA256, with an exact 3.2.3 API/version and little-endian contract. It uses two differently initialized output buffers per identity check to detect unwritten bytes or changed serialization. Checks occur at constructor entry and explicit exit only: no per-step model serialization. The later runner must supply an independently bound expected MJB artifact, call `verify_model_exit()` even after failure, and require both entry and exit verification. Exit closes the adapter against further stepping.

MJB identity is not a portable semantic hash: struct padding, platform/version, visual and statistics bytes can make it stricter than physical equivalence. It does not cover process-global callbacks, arbitrary native collision-table writes, loaded implementation identity, or transient model mutations reverted before exit. Plugins and exposed non-null Python callback getters are rejected, but those getters expose Python-maintained references; they cannot prove absence of direct external C pointer writes. A later isolated runner must pin the actual library/bindings and prohibit concurrent model or native-global mutation. [Callback implementation](https://github.com/google-deepmind/mujoco/blob/3.2.3/python/mujoco/callbacks.cc#L267). No whole-process identity or timing qualification is claimed.

On step/capture failure, the adapter now reads full291 integration, actual actuator forces, qpos, qvel, ctrl, applied external-force arrays, time and both warning arrays independently. It keeps selected target/command and any partially filled failed integration read. A failure in one getter leaves other fields intact. Raw diagnostic evidence gets no returned, captured or verified credit. The original owned returned-capture evidence remains separately preserved. No failure path steps again, forwards, restores or resets state.

Manual PD, strict predicate thresholds, capture schema and the existing clock/history foundation remain unchanged. The foundation's exact repeated-clock equality is stricter than the oracle's 1e-10-second tolerance; a dedicated synthetic test demonstrates that difference. The adapter itself retains the original tolerance, with no observed-time resynchronization.

The tests use Python fake models and a fake complete-byte serializer. They establish adapter behavior under injected mutations, short serialization, native-call exceptions, partial reads, strict violations, history timing and clock drift. They do not establish that the installed native serializer or first restored physical step is bit-identical to the oracle. Those remain later, separately selected native-equivalence work.
