Design only: split the plant from inference before connecting a received-input controller. The smallest useful first test is a scripted command worker with deliberate delays; it should establish the timing and history contract without claiming learned-controller stability. No source implementation, policy call, MuJoCo call, rollout or runtime installation was performed for this note. Exact inspected-file hashes are in `source_pins.json`.

Current code does not provide an independent plant clock. `ClockedSimSession.tick` checks consecutive virtual 20 ms deadlines, then synchronously calls the controller for the entire control interval. `PacedSimSession.tick` measures that same call and recording callback. Its overrun branch sets the next deadline to `finished + 20 ms`; `test_overrun_latches_balance_and_never_catches_up` explicitly expects the rebased deadline and a 45 ms gap. Packet waiting is bounded, but expensive inference or recording still postpones physics. Retain these old results with their declared timing failure; do not reinterpret them as an asynchronous pass.

Use three spawned processes on one host and one immutable monotonic-clock epoch. The plant owns the only actual `MjModel`/`MjData`, native PD stepping, strict per-step checks, applied-command ledger and measured history. It loads everything and allocates all buffers before epoch T0. The policy worker owns ORT sessions and any private simulation data, and receives copied jobs; it cannot call the plant or mutate its state. The supervisor handles received-packet admission, durable output and process status. Neither transport receipt nor disk writes occur synchronously in the plant. A separate logger thread in the supervisor may drain committed records; a slow logger must not hold a plant lock.

Use bounded shared-memory slots and explicit publication ownership, not a blocking Queue put in the plant and not an unprotected multiword Python flag. Each slot has a process-shared lock. A writer tries `acquire(False)`, copies a fixed-size payload and its sequence/version, then releases; a reader also tries once, copies to owned memory, and immediately releases. The plant never waits for a slot. A slot reserved for each of a small fixed set of future activation indices prevents an old result overwriting a newer command. Full/contended slots produce named events and missed work; they do not move the clock. Latest-snapshot replacement, if used, must explicitly mark every superseded policy job; it must never change which source frame belongs to a control. Keep raw source-packet loss distinct from policy-job loss. The supervisor is the only writer to the prepared-input gate; it publishes immutable window IDs and their receipt/dependency clocks.

For the finite foundation test, preallocate the full requested native-state/torque/time/warning trace and deadline/command-event arrays before T0. Size event storage for the declared maximum attempts, including rejected jobs. Publish each completed record index only after its payload is complete. The logger reads committed ranges without modifying them. Exhaustion or recorder corruption ends the run with an explicit failure and retained remaining-step debt; blocking until storage recovers is not allowed. This deliberately avoids promising unbounded, lossless logging with bounded memory. A killed plant is also a failed run, not elapsed simulated time.

The plant has integer physics index n and immutable nominal start deadline D(n) = T0 + n * 2,000,000 ns. The command for control k activates before interval n = 10k, at D(10k), and remains fixed for ten PD steps. The loop waits only until D(n), then executes exactly one unchanged 2 ms PD/MuJoCo step and all checks; it never derives a new epoch from the actual finish time. The next index increments only for a returned step, and attempted, returned, captured and verified counts remain separate on an exception. Expected simulation time retains the original repeated floating addition by 0.002; the integer wall schedule does not replace this numerical check. Each row records nominal start/end, actual start/end, active target ID and wake/finish lateness. A missed completion deadline is `finish > D(n+1)`. A late wake records how many nominal completion deadlines have already elapsed relative to completed steps.

If the plant itself is descheduled, execute remaining indices in order as soon as it runs again, without sleeping until their already-passed deadlines. These are overdue steps, not erased lateness or a timing pass. Keep maximum and cumulative debt plus an immutable first deadline failure. If a predeclared debt/run bound is exceeded, stop with the exact completed prefix and unexecuted scheduled count; do not skip steps, compress ten steps into one larger timestep, reset MuJoCo time or rebase T0. Timing status remains failed even if debt is later repaid. A hung worker should create no such plant debt when the plant has enough CPU; OS contention can, and must remain visible.

Define one control-period command pipeline explicitly. At physical boundary k, the plant activates an already admitted command for k, captures actual state x(k), incoming raw action a(k-1), named/flat history H(k), and the newly active command/action a(k). It publishes a job requesting activation at k+1. The first command is prepared and bound before T0; startup packet acquisition is either before T0 or occurs while the plant runs the declared initial command. It cannot freeze a plant that has already started. A worker result carries run/model/reference hashes, input epoch, job sequence, snapshot physics/control indices, source/window ID, requested activation index, native target, preclip raw action, input/history digests and completion timestamp. The plant admits it only after validating and copying the complete payload into its own future-command slot **before** D(10(k+1)). Plant receipt time after copying and validation is authoritative; a worker timestamp written before a delayed mailbox publication cannot backdate admission. Poll mailboxes opportunistically between native steps, so activation itself only switches an already sealed local slot. An early result waits for its declared boundary. A late or wrong-index result is retained and rejected; it is never applied immediately or shifted to the next control.

On a missed command deadline or latched input fault, carry the last actually activated target and its raw-action provenance mechanically, record a held-command interval, and latch the fault. Continue the plant and strict gates until the fixed run end or an explicit physical/engine failure. This is a clock-foundation behavior, **not a claim that target holding balances the robot**. A balance controller still needs worker computation and physical qualification. Do not call BFM synchronously in the plant on timeout. Ignore subsequent ordinary results while latched. Explicit rearm may change the input epoch only after a separately measured standing criterion; retain physical index, T0, actual state, command history and evidence. Reacquisition is separate from merely clearing the packet buffer.

History belongs to physical controls, not completed inference jobs. The frozen `BFMHistory.before_update` returns the four previous samples, then pushes terms made from current measured q/dq and incoming previous raw action. Reproduce that pure operation exactly once at each actual 50 Hz boundary, including held intervals; record H(k), current terms, outgoing named history and selected a(k). The worker uses a private copy and never commits actual history. Rejected, abandoned or late proposals add no entry. For learned commands retain the original float32 raw combined action before target clipping; for a repeated held command retain its original raw action rather than renormalizing the clipped target. The next entry uses that command as incoming previous action. Preserve initial/terminal raw BFM semantics and report a different command origin explicitly. Existing `LinearStudentRuntime.propose` mutates its seed history and counter before physics; moving that object directly into a worker would let rejected jobs change actual history. Split proposal from activation acknowledgement or use a stateless adapter over the plant's exact snapshot.

One-period latency changes the policy input-to-actuation relation. A command computed from x(k) and applied at k+1 is not the existing zero-delay offline controller, even if it arrives on time. The pipeline exposes this fact rather than hiding it. A later delay-aware simulation worker can restore a **private** full-291 snapshot, replay the already sealed command k for ten steps, advance private history once using measured x(k)/a(k-1), and compute the next proposal from the predicted x(k+1), outgoing history and a(k). This requires the received goal window intended for k+1 to be complete before the calculation; use the existing original-native BFM bank and retargeted residual/original29 task bank, 38 samples plus actual preceding task sample. Source-frame advancement stays fixed by the declared playback epoch; no extrapolation, duplicated padding or source skipping on a late job. Explicit EOF is the only short-window permission.

Any private safety preview must start from that predicted activation state and include the known interim commands. Before activation, compare the produced prediction's full integration state, warnings, time, history and previous action with the actual boundary. A mismatch invalidates that preview and latches the experiment's declared fault; never set the actual state to the prediction. External forces, a held interim command, an epoch change or a missed activation must therefore invalidate the schedule digest. A constant-target forecast from the older captured state is insufficient. This forecast path is a later simulation experiment, not an implementation selection in this note and not proof of estimator or hardware timing.

Concrete adversarial tests should first run against a deterministic fake stepper and spawned stub workers, then against a separately selected native experiment:

1. Stall inference for 100 ms and block its input wait indefinitely. The plant still returns 50 consecutive native steps over the corresponding nominal 100 ms when schedulable; five control boundaries retain their exact command IDs/history entries. No publication from the stuck job can retroactively change them.
2. Hold a mailbox lock in a suspended or killed worker. Plant try-lock returns immediately, records misses, and continues. Flood wrong-index, duplicate, future-epoch and late results; none can replace the sealed target. Inject a 30 ms stall between worker timestamping and publication to catch backdated admission.
3. Deliver two numerically different candidate raw actions whose clipped native targets are identical. Only the activated bundle's raw action enters history. Reject the other bundle and verify complete named-history equality; repeat a held interval and verify there is one measured entry, not one entry per worker attempt.
4. Deschedule the plant for 23 ms with a virtual clock. Every owed 2 ms index is retained, deadlines remain exactly T0+n*2 ms, and the first timing failure/debt remain recorded after catch-up. End while behind and assert the unexecuted count; test a thrown step separately from a returned strict violation.
5. Block the logger and fill its bounded destination. The plant never waits on disk or queues; it either continues within reserved trace capacity or ends with the exact explicit recording failure. Packet producer silence cannot affect this path.
6. Delay/reorder prepared windows, change epoch, omit the preceding task sample and send a short non-EOF window. Admission fails independently of plant stepping; raw receive age and intended playback delay remain distinct. Rearm cannot zero the physics/history counters or silently jump source frames.
7. For a later native pipeline test, compare all actual samples and full endpoint state against replay of the **actual activation ledger**, including held targets. Separately compare predicted activation states to actual states under the sealed interim schedule, then deliberately alter one interim target and ensure preview rejection without plant mutation. Require full-loop wall timing, source tracking and quiet/fault recovery independently; exact offline replay alone is insufficient.

The foundation is implementable using spawn, shared-memory fixed buffers and nonblocking slot locks without changing MuJoCo, policy weights or native limits. It qualifies separation and accounting only. Quiet-machine timing, continuous received-input tracking, dynamic stopping/rearm, held-out motion and hardware remain later evidence gates.
